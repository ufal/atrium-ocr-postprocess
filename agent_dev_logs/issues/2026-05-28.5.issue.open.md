#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) commented at [2026-10-16 12:29](https://github.com/ufal/atrium-ocr-postprocess/issues/5#issuecomment-6215526129):

Landed in v1.12.0-beta: `docs/categorization_logic.md` rebuilt from the code, README Step 4 restructured, and `tests/test_categorization_walkthrough.py` (79 model-free tests that follow a line through pre-filter, language tier, score and gate, covering every override and each page-level pass). The worked-example table in the doc is generated from the test table, so a test fails if they drift.

Two findings to read before signing off:
1. `CATEG_NOISY_SCORE_MAX` (0.80) does not decide `Clear` vs `Noisy`; it only clamps the stored score. The split is the valid-word ratio (< 0.85) and damaged tokens.
2. The Czech-first heuristics (function-word list, `w`/`q`/`x` weirdness, rotation penalty, all-caps code rule, Latin-only vowel class) act on every line whatever its language label, so clean English, German and French lines are treated unevenly (e.g. `The excavation was carried out in 1932.` reads `Noisy`). They are pinned as `known_limit` cases and not changed (frozen for the pilot). The doc ends that section with the post-pilot options and how to measure each with `tools/corpus_change.py`.
