# Strategy — Draft issue #8: Add category ratios to page statistics

> _Prepared 2026-10-22 against `ufal/atrium-ocr-postprocess` `test` at `c28f3ddd63e332a139cff53e21f5615195506a42`. Companion digest: [`../digests/8.digest.md`](../digests/8.digest.md)._

**Status**: 🟡 Pending issue creation and implementation.

## Objective

Extend the existing page-statistics aggregation with five line-category ratios, validate the resulting CSV schemas, document the formulas and rerun statistics over the complete classified corpus.

The change must leave categorization and the existing category counts unchanged.

## Steps

### 1. Confirm the aggregation contract

Inspect `aggregate_STAT.py`, especially `_sum_metrics()` and its two output paths.

Confirm the configured input and output directories, the global statistics filename and the existing rounding conventions. Keep the column names requested by Dana unless a naming change is agreed upon explicitly.

### 2. Implement the ratios

Calculate the ratios from the final category counts for each page:

- `clear_rat = Clear / (num_lines - Empty)`
- `noisy_rat = Noisy / (num_lines - Empty)`
- `trash_ratio = Trash / (num_lines - Empty)`
- `non-text_rat = Non-text / (num_lines - Empty)`
- `empty_rat = Empty / num_lines`

Store decimal fractions rounded to four decimal places.

Use a consistent calculation path so the ratios are available both when scoreable text exists and when a page contains only `Empty` or `Non-text` lines.

### 3. Define edge-case behavior

- If `num_lines - Empty` is zero, the first four ratios are undefined.
- If `num_lines` is zero, `empty_rat` is also undefined.
- Do not emit division-by-zero errors, infinities or misleading zeros for undefined ratios.
- A page consisting entirely of `Empty` lines has `empty_rat = 1.0`.
- For pages with a positive non-empty denominator, the four non-empty category ratios should sum to approximately `1.0`, allowing for rounding.

### 4. Add regression tests

Extend `tests/test_aggregation.py` to cover:

- A page containing a mixture of all five categories.
- A page with no `Empty` lines.
- A page containing only `Empty` lines.
- A page with `Non-text` lines but no `Clear`, `Noisy` or `Trash` lines.
- Zero-denominator behavior and the absence of infinite values.
- Consistent column ordering and values across both aggregation paths.

Use small, deterministic fixtures with independently calculated expected values.

### 5. Update documentation

Update `docs/reference/outputs.md` to describe each new field and its denominator.

Update `docs/usage.md` where it describes the aggregated page-statistics CSVs. Keep the documented output schema consistent with the actual generated files.

### 6. Validate and regenerate the full corpus

After the tests pass:

1. Run the relevant test suite and repository quality checks.
2. Run the aggregation over the complete existing categorized corpus using the intended production configuration.
3. Regenerate all per-document `stats_<doc>.csv` outputs and the global page-statistics CSV.
4. Verify that the intended corpus was processed, document and page output counts are plausible, and no unexpected inputs were skipped.
5. Check representative pages against their source category counts and the five formulas.
6. Compare the new outputs with the previous statistics to confirm that existing category counts and other unchanged fields have not changed.

Record the configuration, output locations, document/page counts, skipped inputs, errors and validation results.

## Done criteria

- [ ] All five requested ratios are implemented and tested.
- [ ] Both aggregation paths produce a consistent schema.
- [ ] Zero-denominator behavior is explicit and tested.
- [ ] Documentation matches the generated output.
- [ ] All relevant tests and quality checks pass.
- [ ] Statistics are regenerated for the full corpus.
- [ ] The rerun and its validation results are documented.

## Out of scope

- Changing line-category definitions or classification thresholds.
- Retraining or replacing classification models.
- Reclassifying the corpus without a demonstrated need.
- Introducing unrelated page-quality metrics.
- Committing the entire regenerated corpus to the source repository without a separate reason.
