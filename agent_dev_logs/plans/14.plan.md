## Goal

A record built from the ATR's docproc reads in the order a person reads the page, and a block continued on the next
page reads as one passage, without moving any layout into the record (D26). A reader of this repository's
documentation meets docproc first, as the default input; every other input format keeps working as it does today.

## Tasks

1. **Order within a page** (`docproc.py`, `read_docproc()` and the block sort at `:255-267`). Keep `readingOrder` as
   the base order, then:
   - footnotes and sidebars (`readingOrderRole`, `metadata.readingOrderExtensions.pages[]`) after the body flow, in
     their own `readingOrder`;
   - a caption (`parentBlockId`) directly after the figure or table it captions;
   - a nested block (`parent`; the figure-OCR child `.t0`) directly after its parent;
   - a missing or `null` `readingOrder` fails the build with a named error instead of sorting first or raising
     `TypeError`.
   Header and footer blocks keep their place. Block `type` decides ordering only; it does not reach the record.
2. **Blocks across pages.** Read `continuedFrom` / `continuedTo`. Lines stay on their own page and keep their own
   numbers. In `content.text` the continuation follows without a page break; a word hyphenated at the join is rejoined
   (the last line ends in `-`, the continuation starts in lower case). A dangling link (target absent) fails the build.
3. **`content.text`** (`build_record.py:215`): a blank line between blocks and between pages, so the passage
   structure survives for the enrichment steps.
4. **Tables without `cellGrid`** (`docproc.py:201-206`): parse an HTML or pipe-table `content` into one line per row,
   cells joined by a tab, as for `cellGrid`; unparsable markup fails the build rather than reaching the record.
5. **Scoring stays on the new order.** `record_scoring.document_passes()` numbers lines in record order
   (`record_scoring.py:139-157`); nothing to change there, but the tests check that a footnote moved after the body
   no longer sits between two body lines in the neighbour passes.
6. **Fixtures and tests.**
   - Extend the hand-written ATR fixtures (`tests/fixtures/docproc/*.atr.docproc.json`): a paragraph across two
     pages with a hyphenated join, a footnote and a sidebar with roles and extensions, a caption and a `.t0` child,
     running header/footer clusters, a two-column page, a table with only HTML `content`.
   - Tests in `tests/test_build_record.py` and a reader test for the order rules; `tests/test_docproc_merge.py`
     unchanged except where the order changes the merged output.
   - **Acceptance:** Ronald's real samples added as fixtures (with his consent), each building a record that passes
     the hub's `e2e_assert.py --docproc`.
7. **Reader docs:** the reader section of `service/README.md` (`:251-271`) and `docs/usage.md` (`:591-625`) describe
   the order and continuation rules.
8. **Docs: docproc first** (from the issue body). No code default changes: every reader, `run_pipeline.py` and
   `POST /process` keep working as they do.
   - `README.md`: the title and introduction (`:1-6`) describe a tool that builds the ATRIUM record from a document's
     docproc and scores every line, and also reads OCR and other text formats; the inputs table (`:13-18`) lists
     docproc first; the quick start (`:42-73`) shows `POST /build_record` on a docproc fixture
     (`tests/fixtures/docproc/`), then the batch pipeline; "How it works" (`:75-80`) starts from docproc.
   - `docs/usage.md`: the docproc route (`build_record.py`, now `:591`) before the ALTO-based stages, which stay as the
     batch and research path (`:61-590`).
   - `service/README.md`: the worked request ("Request example", `:93`) on `/build_record`; `/process` after it.
   - `docs/text_inputs.md`: docproc as the first row of "OCR and layout formats" (`:39-45`), with its standard (ARÚP's
     schema, atrium-project#84 comment 1).
   - Not here: the hub's `docs_site/workflows/ocr-postprocess.md`, which tells the same ALTO-first story — noted for
     the hub's docs.

## Out of scope

ALTO and its readers (D24: kept, no longer the default); any layout field in the record (D26: the record links lines
to blocks by `lines[].block`); the merge rule of H6 itself; scoring rules 1–8 (frozen for the pilot, rule 8).

## Done when

A record built from each real ATR sample has its body, footnotes, captions and figure OCR in reading order; a
paragraph continued across pages reads as one passage in `content.text`; the hub's `e2e_assert.py --docproc` passes;
the README, usage, service and input-format pages present docproc as the default input; the fast suite is green. One
PR into `test`, described, reviewed, squash-merged.
