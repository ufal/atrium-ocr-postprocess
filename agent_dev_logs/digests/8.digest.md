## 🎯 Goal

Add normalized line-category ratios to the page-statistics outputs so that pages can be compared more meaningfully regardless of the number of lines they contain. After implementation and testing, regenerate the statistics for the complete classified corpus.

The request comes from Dana's review of the completed line categorization. The existing output already contains page-level category counts, which are useful for assessing the quality of OCR output. The additional ratios should make comparisons between pages more interpretable.

## 📩 Dana's request

Dana proposes five new columns:

| Column | Formula |
|---|---|
| `clear_rat` | `Clear / (num_lines - Empty)` |
| `noisy_rat` | `Noisy / (num_lines - Empty)` |
| `trash_ratio` | `Trash / (num_lines - Empty)` |
| `non-text_rat` | `Non-text / (num_lines - Empty)` |
| `empty_rat` | `Empty / num_lines` |

`Empty` lines are excluded from the denominator of the first four ratios, but included in the denominator of `empty_rat`.

Dana also requests that the complete statistics set be generated again with these columns included.

## 🔎 Current baseline

The page-level aggregation is implemented in `aggregate_STAT.py`.

The current pipeline produces:
- Per-document statistics in `stats_<doc>.csv` files under the configured statistics output directory.
- A global page-statistics CSV, configurable through the aggregation settings.
- Existing category counts, totals, numeric averages and language information.

The aggregation handles pages with and without scoreable text through separate paths. Both paths must produce the same output schema after this change.

Relevant files:
- `aggregate_STAT.py`
- `tests/test_aggregation.py`
- `docs/reference/outputs.md`
- `docs/usage.md`

Current page statistics include the line-category counts but do not yet document or calculate the five requested ratios.

## ✅ Acceptance criteria

1. Add all five requested columns to the page-statistics outputs.
2. Calculate the ratios according to Dana's definitions, retaining decimal fractions rather than percentages.
3. Round ratios to four decimal places.
4. Handle zero denominators without division errors or infinite values. For pages consisting entirely of empty lines, the first four ratios are undefined and `empty_rat` equals `1.0`.
5. Ensure both aggregation paths return consistent columns.
6. Add tests for normal pages, missing categories, empty-only pages and zero-denominator handling.
7. Update the output reference and usage documentation.
8. Regenerate statistics across the complete corpus using the existing categorized line data.
9. Verify that the run covers the intended inputs, that outputs are present and that existing category counts and statistics remain unchanged.

## 📌 Scope boundaries

- This issue concerns page-level statistics, not line categorization.
- No category definitions, thresholds, scoring rules or line-classification behavior should change.
- The full-corpus rerun should reuse the completed line-classification outputs unless a concrete problem requires otherwise.
- The full dataset must be validated; sample CSVs alone are insufficient.
- Generated corpus outputs should be written to the established data/output locations rather than committed wholesale to the source repository unless the project's existing data-management practice requires it.
