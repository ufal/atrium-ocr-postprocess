## 🧭 Where it stands — 2026-11-06

### What the issue asks

- **The question:** can a decision model settle the lines that the rule cascade (`determine_category()`,
  `text_util.py`) is least sure of?
- **How the model answers:** it returns a probability for each of `Clear`, `Noisy`, `Trash` and `Non-text`. It writes
  no text.
- **Where the answers go:** a sidecar table, `DOC_LINE_DECIDE/<doc>.csv`. `categ`, the record and `PAGE_ALTO/` are not
  touched.
- **The selected lines** (five tags):

| Tag | Population                                                        | Why it is uncertain                                                       |
|-----|-------------------------------------------------------------------|---------------------------------------------------------------------------|
| S1  | ≤ 3 tokens, no Czech diacritics, read `Clear` or `Noisy`          | ~26,000 garbage lines read `Clear`; 13.9 % of 484 graded promotions wrong |
| S2  | a 9a–9f red flag fired without a conviction                       | the flag only shows through `rule_fire_capture()`                         |
| S3  | raw score within ±0.05 of 0.55, or valid-word ratio near 0.85     | the stored score is clamped into its band                                 |
| S4  | a confident non-Czech/Slovak line read `Noisy`                    | the rules are Czech-first                                                 |
| S5  | a document pass changed the line                                  | votes and page context override the line's own evidence                   |

- **The judge:** the 2,067-line gold set (`tools/gold/sidecars/issue30_gold_2067.csv`), split by document into dev and
  test. It is scored by the existing verdict of `tools/recategorize_from_csv.py --gold-column gold_categ`: gold errors
  must fall, and `Clear`-loss must not rise. The #30 annotations are a second test set.
- **The models:** Clef first; then Clef-Flash; then Strands Decider 2B. Strands reads text and runs on a CPU, so it is
  the cost target here.

### The server and the data (new on 11-06)

- **Pavel's internal ÚFAL endpoint** serves Clef as `clef-oQ8e`.
  - Clef-Flash and Strands are not served there.
  - `oQ8e` reads as an 8-bit build; it is to be confirmed and recorded.
  - The host is not written in this public repository.
- **The gold set is public only as keys and labels.** The line text it labels is on the cluster, in the `2907` batch
  (`GOLD.md`). Every selected line is therefore archive text. Sending it to the endpoint, which is outside the
  cluster, waits for motyc's answer on the umbrella.
  - Until then: the selector and its counts, and the client's selftest.
  - Model runs can also use a server started on the cluster.

### What is shared

- **The client:** `decision_client.py` comes from page-classification, pinned in
  `tests/test_vendored_decision_parity.py` (`VENDORED` + `ADOPTED`). That follows `docs/shared_components.md` in the hub.
- **Settings:** while the work is offline, they are CLI flags, listed under `NOT_PUBLISHED` in
  `tests/env_contract_data.py`.

## ⚠️ Limits

- **The pilot freeze binds:** no rule, threshold, column, record field or default changes. An adoption is its own
  issue after the freeze. It would be a flag-off hook after `determine_category()` in `score_line()`, measured first
  with `tools/corpus_change.py`.
- **OCR text sent as state is untrusted input.** An answer never deletes or rewrites a line.
- **Thresholds are bound** to one model build and one wording, are set on dev, and are frozen before test.
- **Which stage runs next** stays a rule over counts, in the orchestrator (`atrium_document.py`).
- **No hosted inference on archive text.** The internal endpoint is not hosted inference, but it is outside the
  cluster, hence the data question.
- **Not #4:** no LLM text correction. The adjudicated lines may later serve #4's distillation, once checked against
  gold.
